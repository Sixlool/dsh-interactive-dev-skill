# 示例：架构决策点提问

> 来自 DSH Desktop Pet 实战。架构文档写完后，把剩余未定项压缩成「一次一个决策组」。

## 决策组 1（持久化 + 按钮位置）

```text
Q1 持久化深度：
  - A. Host 内存（推荐）——覆盖"刷新/重开页面"主场景，零风险
  - B. 加 fs 落盘（跨完整重启）——受沙箱策略影响，需实测

Q2 开关按钮位置：
  - A. 侧边栏底部（推荐）——全局常驻
  - B. 会话页头部——仅会话页可见
  - C. 两处都放
```

## 为什么这样收敛

- 架构文档（design.md）已经把能定的都定了（Slot、事件映射、RPC 契约）
- 只剩 2 个真正影响实现的决策 → 一次问完，不拖第二轮
- 每个选项描述写清**代价**（tradeoff），用户不需要懂技术也能选

## 配套原则

- 决策点 ≤ 2 题一组；问完立即开工，不反复确认
- 用户没意见的选项（如仓库名）由 agent 自定并在交付时说明，不占用提问额度
