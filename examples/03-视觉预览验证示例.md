# 示例：视觉预览验证循环

> 来自 DSH Desktop Pet 实战。任何图形/UI 交付物在实装前先走这个循环，避免"改完还是丑"。

## 循环步骤

1. **写 preview.html**：把设计画成静态页。图形类（桌宠/SVG/立绘）把**所有状态并排**（待机 / 思考 / 完成 / 出错），同一张图里对比
2. **无头渲染**：`vision_html_screenshot`（可指定 width/height）
3. **AI 复查**：`vision_describe` 带具体问题逐项检查——比例、重叠、遮挡、位置错乱、美观度；让模型明确说"OK"或列问题
4. **修改 → 重渲染**：不满意就改 SVG/HTML 再截图，循环直到 OK
5. **实装**：把验证过的设计（SVG 元素/图片引用）翻译进插件代码（cordis_define → update）

## 桌宠实战案例

- 第 1 版（纯 SVG 猫）：AI 复查指出"手悬浮、脚位置怪、笑嘴偏低" → 改 5 处 → 复查 OK → 实装
- 第 2 版（立绘抠图）：抠图 → 缩小 → 放 preview 模拟桌宠场景截图 → 给用户亲眼看效果 → 确认后实装
- 第 3 版（换形象）：用户给参考图 → SVG 重绘 → 预览 → AI 复查 → 用户拍板

## 要点

- 预览页放**深色背景 + 模拟真实场景**（截图和真实效果接近）
- 视觉模型限流时：直接 `vision_present` 把截图给用户看，让用户判断
- 图片资源先用本地路径，实装时再处理传输（base64 data URI / fs 读取）
